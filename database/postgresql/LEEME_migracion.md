# NOVA SOUND — Migración a PostgreSQL

Se convirtieron los dos scripts originales `nova_sounds.sql` e `inserts_nova_sounds.sql` que compartió el equipo.

## Contenido

- `00_crear_base.sql`: crea la base `nova_sounds` (sin espacios).
- `01_esquema_postgresql.sql`: crea las **25 tablas** y conserva las claves foráneas/únicas del esquema MySQL.
- `02_datos_postgresql.sql`: importa los registros originales, incluidas **50 unidades**, pruebas, inspecciones y defectos; reajusta las secuencias de identidad.
- `03_verificacion_postgresql.sql`: permite comprobar las tablas y los principales conteos.

**Orden obligatorio: 00 → 01 → 02 → 03.** Ejecuta cada archivo una sola vez sobre una base nueva y vacía.

## Ejecución usando psql desde Fedora

Si es una instalación nueva de PostgreSQL en Fedora (sin un clúster ya inicializado):

```bash
sudo dnf install postgresql postgresql-server
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
```

No vuelvas a ejecutar `--initdb` si ya existe una instancia PostgreSQL inicializada. Después, desde el directorio que contiene los scripts:

```bash
sudo -u postgres psql -v ON_ERROR_STOP=1 < 00_crear_base.sql
sudo -u postgres psql -d nova_sounds -v ON_ERROR_STOP=1 < 01_esquema_postgresql.sql
sudo -u postgres psql -d nova_sounds -v ON_ERROR_STOP=1 < 02_datos_postgresql.sql
sudo -u postgres psql -d nova_sounds -v ON_ERROR_STOP=1 < 03_verificacion_postgresql.sql
```

En Windows, con `psql` instalado y autenticación configurada, usa comandos equivalentes:

```powershell
psql -U postgres -d postgres -v ON_ERROR_STOP=1 -f 00_crear_base.sql
psql -U postgres -d nova_sounds -v ON_ERROR_STOP=1 -f 01_esquema_postgresql.sql
psql -U postgres -d nova_sounds -v ON_ERROR_STOP=1 -f 02_datos_postgresql.sql
psql -U postgres -d nova_sounds -v ON_ERROR_STOP=1 -f 03_verificacion_postgresql.sql
```

## Cambios SQL realizados

| MySQL | PostgreSQL |
|---|---|
| `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` |
| `DATETIME` | `TIMESTAMP WITHOUT TIME ZONE` |
| `BOOLEAN` con valor de muestra `1` | `BOOLEAN` con `TRUE` |
| `CREATE DATABASE IF NOT EXISTS`, `USE`, `SHOW TABLES` | Creación de DB por separado y consultas de verificación |
| `NOVA SOUNDS` (nombre con espacio) | `nova_sounds` |

PostgreSQL guarda los identificadores sin comillas en **minúsculas**, por ejemplo `Roles` → `roles`.

`BY DEFAULT AS IDENTITY` permite insertar IDs explícitos presentes en el dataset. El bloque de resíncronización actualiza las secuencias para que insertar nuevos registros después no produzca colisiones.

## Consideraciones antes de usarlo con FastAPI

1. **Contraseñas de prueba:** `pass123` está en texto plano en los inserts originales. Reemplaza estos datos por hashes de contraseña antes de cualquier login real.
2. **Datos de demostración:** el modelo `Modelo SoundPro X` y los turnos `07:00–15:00` / `15:00–23:00` son los originales; no se corrigieron para no alterar los datos sin autorización. El caso de NOVA SOUND menciona otros modelos y horarios.
3. **Pruebas funcionales:** el esquema actual guarda un resultado global en `pruebas`, no cuatro campos de prueba individual. Ese es un ajuste funcional pendiente, distinto de la migración de motor.
4. **Estados:** el script original utiliza `EMPACADA` como estado en registros de calidad; se conserva para evitar introducir una modificación no validada en la migración.
5. **Datos ilustrativos:** algunos timestamps y asociaciones de ejemplo pueden no representar una operación industrial consistente; no se han normalizado ni corregido.
6. **No incluye la migración de datos vivos** posteriores a los inserts: convierte los dos scripts entregados, no realiza una exportación de un servidor MySQL en funcionamiento.
7. **No es repetible:** si ejecutas `02` dos veces sin vaciar la base, puedes recibir errores de IDs o datos duplicados.
